# S3 → EventBridge → Step Functions → Glue → Snowflake SP1 → SP2 Pipeline

## 1. Raw CSV File Arrives in S3

A CSV file is uploaded into the **Raw S3 Bucket**.

```text
S3 Raw Bucket
     │
     │ CSV Upload
     ▼
EventBridge
```

EventBridge detects the new CSV file and starts the **single Step Functions state machine**.

---

## 2. Step Functions Starts the Glue Job

Step Functions invokes **Lambda 1**.

Lambda 1 starts the **AWS Glue Job**.

```text
S3 Raw
   │
   ▼
EventBridge
   │
   ▼
Step Functions
   │
   ▼
Lambda 1
   │
   ▼
Glue Job
```

The Glue Job performs data cleansing on the raw CSV file.

### Glue Job Responsibilities

The Glue job:

- Reads the CSV file from the Raw S3 bucket.
- Removes `NULL` / unwanted null records according to the business rules.
- Removes duplicate records.
- Performs required basic data-quality cleansing.
- Writes the cleaned data into the **Refined S3 Bucket**.

```text
Raw S3 Bucket
      │
      ▼
   Glue Job
      │
      ├── Remove NULLs
      ├── Remove Duplicates
      └── Data Cleansing
      │
      ▼
Refined S3 Bucket
```

---

## 3. Step Functions Waits for Glue

After Lambda 1 starts the Glue Job:

- Lambda 1 returns the **Glue Job Run ID** to Step Functions.
- Step Functions stores the Job Run ID.
- Step Functions enters a **Wait State**, for example 3 minutes.
- After the wait, Step Functions invokes **Lambda 2**.

Lambda 2 checks the Glue Job status using the Job Run ID.

Possible statuses:

```text
RUNNING
SUCCEEDED
FAILED
STOPPED
```

### If Glue is RUNNING

Lambda 2 returns:

```text
RUNNING
```

Step Functions:

```text
Wait 3 Minutes
      │
      ▼
Check Glue Status
      │
      └── RUNNING
              │
              ▼
         Wait 3 Minutes
              │
              ▼
        Check Again
```

This continues until Glue reaches a final state.

---

## 4. Glue Successfully Creates the Refined File

When Glue completes successfully:

```text
Glue = SUCCEEDED
```

The cleaned CSV is available in the **Refined S3 Bucket**.

```text
Raw CSV
   │
   ▼
Glue
   │
   ├── NULL removal
   ├── Duplicate removal
   └── Data cleansing
   │
   ▼
Refined S3
   │
   └── Clean CSV
```

At this point, **we do NOT trigger another Step Functions state machine**.

The existing Step Functions execution simply continues to the next state.

This keeps the architecture to **ONE Step Functions state machine**.

---

## 5. Start SP1

Step Functions now invokes **Lambda 3**.

Lambda 3 connects to Snowflake and starts **Stored Procedure 1 (SP1)** asynchronously.

SP1 reads the cleaned/refined data and loads it into the **Staging Table**.

```text
Step Functions
      │
      ▼
Lambda 3
      │
      ▼
Snowflake SP1
      │
      ▼
Staging Table
```

Lambda 3 captures the **Snowflake Query ID** generated by SP1 and returns it to Step Functions.

---

## 6. Wait and Monitor SP1

Step Functions waits for **3 minutes**.

After 3 minutes, Step Functions invokes **Lambda 4**.

Lambda 4 uses the SP1 **Query ID** to check the Snowflake query status.

Possible statuses:

```text
RUNNING
SUCCESS
FAILURE
```

### If SP1 is RUNNING

Lambda 4 logs the status:

```text
SP1 Status = RUNNING
```

and returns `RUNNING` to Step Functions.

Step Functions waits another 3 minutes and checks again.

```text
              ┌───────────────┐
              │   Start SP1   │
              └───────┬───────┘
                      │
                      ▼
                Wait 3 Minutes
                      │
                      ▼
              ┌───────────────┐
              │ Check SP1     │
              │ using Query ID│
              └───────┬───────┘
                      │
             ┌────────┼────────┐
             ▼        ▼        ▼
          RUNNING   SUCCESS   FAILURE
             │        │        │
             ▼        ▼        ▼
        Wait 3 Min   SP2     Failure
             │
             └──► Check Again
```

---

## 7. SP1 Success

When Lambda 4 detects:

```text
SP1 = SUCCESS
```

SP1 has completed successfully.

SP1 also records the required information in **Audit Table 1**.

Step Functions then moves to the SP2 process.

---

## 8. Start SP2

Step Functions invokes **Lambda 5**.

Lambda 5 starts **Stored Procedure 2 (SP2)**.

SP2 reads the data from the staging table and performs the required transformations and loading.

```text
Staging Table
      │
      ▼
     SP2
      │
      ├──────────► Dimension Tables
      │
      ├──────────► Fact Table
      │
      └──────────► Audit Table 2
```

SP2 performs:

- Data transformation
- Dimension loading
- Fact loading
- Required business logic
- Validation
- Audit logging

---

## 9. SP2 Completion

After SP2 completes, Lambda 5 receives/logs the result.

Possible result:

```text
SUCCESS
FAILURE
```

The result is passed back to Step Functions.

---

## 10. Email Notification

Step Functions evaluates the final status.

### SUCCESS

If SP2 succeeds:

```text
Step Functions
      │
      ▼
Email Lambda
      │
      ▼
SES
      │
      ▼
User
```

The user receives:

```text
Pipeline Status: SUCCESS
```

### FAILURE

If Glue, SP1, or SP2 fails:

```text
Step Functions
      │
      ▼
Email Lambda
      │
      ▼
SES
      │
      ▼
User
```

The user receives:

```text
Pipeline Status: FAILURE
```

along with the relevant error/status information.

## Final Logical Flow

```text
S3 RAW
  ↓
EventBridge
  ↓
ONE STEP FUNCTIONS
  ↓
Lambda
  ↓
Start Glue Job
  ↓
Wait + Check Glue Status
  ↓
Glue SUCCESS
  ↓
Refined S3
  ↓
Continue Same Step Functions Execution
  ↓
Lambda
  ↓
Start SP1 Async
  ↓
Wait 3 Minutes
  ↓
Lambda Checks SP1 using Query ID
  ↓
SP1 RUNNING → Wait 3 Minutes → Check Again
  ↓
SP1 SUCCESS
  ↓
Lambda
  ↓
Start SP2
  ↓
SP2
  ├── Dimension Tables
  ├── Fact Table
  └── Audit Table 2
  ↓
SUCCESS / FAILURE
  ↓
Email Lambda
  ↓
SES
  ↓
User
```

---

## Important Correction

The **Refined S3 → EventBridge → Lambda → Child Step Functions** part is removed.

You only need **one Step Functions execution**. The Step Functions workflow itself waits for the Glue job to finish, confirms that the refined file was created, and then continues directly to **SP1 → SP2 → notification**.

This makes the orchestration much cleaner and avoids creating a second/child Step Functions execution.
